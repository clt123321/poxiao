1. **EvoWorld：让视频模型推理"视线之外"的世界演化（面向视外世界演化的生成式视频模型）**

   🔬 领域：视频生成 · 世界模型 · 因果推理 · 热度：HF Daily Papers TOP 10

   - **一句话核心贡献**：提出"Out-of-Sight Causal Evolution（视线外因果演化）"新问题，并给出 EvoWorld 基线方案——以视觉语言模型作"世界大脑"维护状态账本、推理事件后果，由分段自回归视频渲染器把推理结果可视化，让视频模型从"画得好看"走向"推得合理"。
   - **摘要精译**：
     生成式视频模型越来越多被当作视觉世界模拟器使用，但它们的强项只是渲染可信的像素，而非推理一个世界应当如何演化；当事件发生时，模型必须推断其对世界中实体的后果，再渲染出随之而来的状态——例如野兽出现后，旁边的人应逃开、掩护还是反击，现有扩散视频模型缺乏显式的世界状态维护与基于事件后果的推理机制，常产出"看着合理但行为静止或因果不一致"的输出。为此作者把这一推理缺口具体化为可测量的新问题：要求模型渲染事件、推理其对演化世界状态的后果，并在世界继续演化（哪怕离开视线）时揭示因果上合理的结局。EvoWorld 采用"大脑-渲染器"协作框架：VLM 作为世界大脑，观测已生成片段、持续维护世界演化账本、推理合理状态转移；专用视频渲染器负责视觉实现；同时配套 EvoWorld-Data 训练数据与 EvoWorld-Bench 评测基准，覆盖事件实现、因果反应与回访一致性。实验表明，EvoWorld 在事件条件因果演化上显著优于近期模型，同时保持视觉质量与一致性，为"推理引导的自主世界演化"建立了参考点。
   - **核心创新点**：
     1. 首个"视线外因果演化"评测问题
     2. VLM 世界大脑 + 分段渲染器协作
     3. 配套训练数据与评测基准

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：VLM 世界大脑逐段观测渲染输出，维护实体与状态的世界账本（world account），推理"事件 → 状态转移 → 后果"链；渲染器以分段自回归方式把推理出的新状态视觉化，形成"推理-渲染"闭环。EvoWorld-Data 用于训练事件实现与因果反应，EvoWorld-Bench 用于评估事件实现、因果反应、回访一致性三个维度。
   - **实验结果**：在事件条件因果演化上相对近期扩散视频模型显著提升，视觉质量与一致性不降——
     论文未给出单一数字式总成绩，以"substantially improves … while preserving visual quality and consistency"表述，具体分数见 EvoWorld-Bench 论文附表。
   - **局限性**：基线方案依赖 VLM 推理与渲染器的耦合质量；评测基准为合成数据构建，真实开放世界演化的泛化性有待验证。

2. **Video-Coder：用强化学习训练"会写代码"的视频生成 Agent**

   🔬 领域：视频生成 · Agentic Coding · 强化学习 · 热度：HF Daily Papers TOP 10

   - **一句话核心贡献**：首个代码驱动的视频生成 Agent 训练尝试——模型自主编写并执行代码构建动态 3D 草稿场景（Draft Video），为下游视频生成器提供结构与运动信号，再经 SFT + 带双奖励的 Agent 强化学习训练，在 Minimax-H3 上把 PhyGenBench 提升约 7 分、VBench-2.0 提升 24 分。
   - **摘要精译**：
     近年来视频生成在视觉质量与时序一致性上进展显著，但生成具备精确空间结构、连贯运动动力学、可控场景构图的视频仍是难题，纯像素级生成难以显式表达"物体在哪里、怎么动、场景如何组织"。Video-Coder 提出让 Agent 自己写代码：自动编写并执行代码来构建动态 3D 场景作为"草稿视频"，向下游视频生成器提供结构与运动信号；为此设计专门数据管线，整理 Video-Coder-SFT-6k 与 Video-Coder-RL-2k 两个高质量数据集，并构建 Video-Coder Harness 统一交互环境（集成代码执行、3D 场景渲染与执行反馈）。训练采用 SFT 后接 harness 原生 Agent 强化学习，结合执行奖励与视频奖励双反馈，并用退火策略逐步降低执行奖励权重，使模型后期更多依赖视频奖励。实验显示，Video-Coder 使 Minimax-H3 在 PhyGenBench 上提升约 7 分、在 VBench-2.0 上提升 24 分，且数据、模型与代码全部开源，可作为视频生成编码 Agent 的开放基础。
   - **核心创新点**：
     1. Agent 写代码构建 3D 草稿场景
     2. 执行+视频双奖励 Agent 强化学习
     3. 执行奖励退火的渐进训练策略

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：训练分两阶段——先用 6K 条 SFT 数据教会 Agent"提示词 → 代码 → 3D 场景"映射，再用 2K 条 RL 数据做 harness 内 Agent 强化学习；奖励由执行反馈（代码能否运行出预期 3D 场景）与视频质量（生成视频与参考视频的相似度）两个信号组成，训练后期通过退火减少执行奖励占比。
   - **实验结果**：Minimax-H3 + Video-Coder 在 PhyGenBench 提升约 7 个点、VBench-2.0 提升 24 个点（"approximately 7 points on PhyGenBench and 24 points on VBench-2.0"）。
   - **局限性**：依赖 3D 场景中间表示的渲染成本；代码执行环境引入额外延迟，推理链路比端到端生成更长。
   - **链接**：https://arxiv.org/abs/2611.09894

   </details>

3. **SplatAnything：高斯间距归一化，扫清前馈 3DGS 的跨场景重建障碍**

   🔬 领域：3D 表示 · 前馈 3DGS · 多视图重建 · 热度：HF Daily Papers TOP 10

   - **一句话核心贡献**：识别前馈 3DGS 的"径向距离归一化空间"导致高斯间距在跨场景尺度/相机配置下剧烈变化、监督目标系统性偏移的问题，提出 GSNorm（高斯间距归一化）为高斯预测提供一致的空间参照，跨场景尺度与视角实现全面 SOTA。
   - **摘要精译**：
     现有前馈 3DGS 方法通常在一个"径向距离归一化"空间预测高斯属性，该空间对重建几何的全局径向统计做规范化，但相邻高斯中心之间的间距仍会随场景尺度与相机配置大幅变化——这种失配使高斯尺度目标发生系统性偏移，形成模糊监督。为修正这一点，SplatAnything 提出高斯间距归一化（GSNorm）：规范化一个稳健的场景级高斯间距统计量，为高斯预测提供更一致的空间参考。为严格评估，作者构建了覆盖多数据集、不同输入稀疏度与具有挑战性的外推视点的系统基准。大量实验表明，SplatAnything 达到当前最优性能，且在场景尺度与视点显著变化的条件下提升尤为突出。
   - **核心创新点**：
     1. 识别间距-归一化空间失配问题
     2. 场景级间距统计量 GSNorm
     3. 跨尺度/视点系统评估基准

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：GSNorm 用稳健场景级统计量（而非全局径向统计）对高斯间距做归一化，消除跨场景尺度漂移导致的监督模糊；配合重建时的高斯预测网络整体训练，无需改变推理流程。
   - **实验结果**：论文表述为"SOTA performance, with particularly strong gains under substantial variations in scene scale and viewpoint"，具体数据集上的 PSNR/SSIM 数值见论文正文与附表（多数据集 × 稀疏度 × 外推视点网格）。
   - **局限性**：归一化依赖输入视图的质量与覆盖率；外推视点极稀疏时提升幅度收敛，极端场景下仍有重建退化。
   - **链接**：https://arxiv.org/abs/2611.08264

4. **LongBanana：首个专家验证的长上下文多参考图像合成基准**

   🔬 领域：多模态 · 图像生成 · 评测基准 · 热度：HF Daily Papers TOP 10

   - **一句话核心贡献**：构建首个由专家设计与验证的长上下文多参考图像合成基准——3×3 分类法组织 90 个任务、共 4,670 个专家原子评测项，并配套 Agent 框架 LongBanana-Gen，实验显示其 RPR 工作流能强化证据接地、提升 Agent 驱动的长时序图像生成。
   - **摘要精译**：
     在 Agent 驱动的图像生成时代，模型需要从多张参考图中检索分散的视觉证据、拒绝干扰项、绑定实体与关系，再合成一张连贯的最终图像，而此前缺乏针对这一长上下文能力的严谨评测。LongBanana 共含 90 个精心设计的任务（3×3 分类法组织），每个任务约 32 张参考图像、20 条约束、50 个评测项，总计 4,670 个专家指定的原子评测项。其图锚定（graph-grounded）评测设计把每个任务实例化为参考图 + 实体-关系图，再将节点、边、全图义务转换为内容保真度（Content Fidelity）、关系绑定（Relational Binding）、全局约束满足（Global Constraint Satisfaction）三类检查清单；标注评审中包含 15% 双重标注子集，精确一致率 89.4%、二次加权 kappa 0.83。作者还推出 LongBanana-Gen Agent 框架：实验表明最简 Agent 框架即优于直接生成，而 ReAct-Plan-Exec-Reflect（RPR）工作流通过强化证据接地与修复带来框架相关的进一步提升。
   - **核心创新点**：
     1. 90 任务 + 4,670 原子评测项
     2. 图锚定的三重维度检查清单
     3. RPR 工作流强化证据接地

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：任务创建基于 3×3 分类法（上下文长度 × 合成复杂度），每个任务由专家把实体-关系图转化为原子检查清单；评测时逐项核对生成图像，覆盖内容保真、关系绑定与全局约束。LongBanana-Gen 提供 Agent harness，支持直接生成、最简 Agent 与 RPR 三种工作流对比。
   - **实验结果**：15% 双重标注子集精确一致率 89.4%、二次加权 kappa 0.83；最简 Agent harness 一致优于直接生成，RPR 工作流在证据接地与修复上带来额外提升。
   - **局限性**：基准聚焦静态图像合成，视频/交互式生成尚不覆盖；专家标注成本高，任务规模（90）相对有限。
   - **链接**：https://arxiv.org/abs/2611.06856

   </details>

5. **Fast and Exact Relative-Position Attention：结构感知 Kernel 让相对位置注意力精确且高效**

   🔬 领域：推理 · Transformer 架构 · 注意力 Kernel · 热度：HF Daily Papers TOP 10

   - **一句话核心贡献**：把带加性相对位置项的注意力精确融入 FlashAttention 式分块计算，提供统一的 Triton 实现覆盖多种相对位置注意力机制——8K 序列下前向提速 1.8–6.4 倍、峰值显存最高降至 1/128，是相对位置注意力 Transformer 即插即用的硬件高效方案。
   - **摘要精译**：
     相对位置注意力机制是 RoPE 在多种 Transformer 架构上的强有力替代，在音频等域表现更优；但它通常需要逐对（pairwise）的 offset 相关计算或查表，难以融入融合注意力 Kernel，随序列变长带来严重的显存、带宽与计算开销。本文提出精确注意力算法，把加性相对位置项纳入 FlashAttention 式分块计算：(1) offset-aware 分块避免冗余索引与内存访问；(2) 只计算必要的 key/query 关系乘积，并在前向与后向中跨 token 对复用；(3) 基于 offset 的梯度分片与聚合消除原子竞争。作者给出覆盖多种相对位置注意力机制的统一高效 Triton 实现，并与朴素/专用实现对比：8K 序列上前向（后向）相对各机制最强基线提速 1.8–6.4 倍（2.0–21 倍），峰值显存降低最多 2.9–128 倍（1.4–54 倍），端到端长上下文转录快 1.8 倍、显存占用少 2.4 倍。
   - **核心创新点**：
     1. offset-aware 分块避免冗余访存
     2. 前后向复用 key/query 关系乘积
     3. offset 梯度分片消除原子竞争

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：在 FlashAttention 规格的分块计算中加入加性相对位置项；挑战在于位置相关的偏置项破坏标准 tile 内复用，作者用 offset-aware tiling 保证索引一致性，在 forward/backward 全程复用关系乘积，并用 offset 分片梯度消除原子操作竞争。实现为统一 Triton kernel，一段代码覆盖多种相对位置机制。
   - **实验结果**：8K 序列，forward（backward）相对各机制最强基线 1.8–6.4×（2.0–21×）加速；峰值显存最高降低 2.9–128×（1.4–54×）；端到端长上下文转录快 1.8×、省 2.4× 显存。
   - **局限性**：当前以 Triton 实现为主，是否直接支持特定厂商加速器需要进一步适配验证；对比主要面向注意力 kernel 层面，未做全模型端到端 benchmark 覆盖。
   - **链接**：https://arxiv.org/abs/2611.01182

   </details>

6. **LowRAM：键低秩 + 值摊销，KV Cache 测试时压缩做到 26.9×**

   🔬 领域：ML 系统 · KV Cache 压缩 · 推理优化 · 热度：HF Daily Papers TOP 10

   - **一句话核心贡献**：利用"注意力头内值向量大致可由键预测"这一新冗余维度——测试时拟合按头轻量预测器只存最差 token 残差（4× 近无损值压缩），配跨层低秩键压缩组成 LowRAM 非对称管线，解码吞吐最高提升 5×，并与量化/驱逐组合达到 26.9× 总压缩（长上下文保持基线 94.5% 性能）。
   - **摘要精译**：
     自回归解码依赖 KV cache，其显存随上下文长度线性增长，限制批量大小与吞吐；现有后训练方法主要利用 token/层/特征维度冗余或降低数值精度。本文识别出互补的冗余轴：在每个注意力头内部，值在很大程度上可由对应键预测。据此提出值缓存摊销：测试时为每个头拟合轻量预测器，只存储预测最差 token 的残差，实现 4 倍近无损值压缩；预测器可由元学习初始化以大幅降低 prefill 开销，也可在允许一次性成本时从头拟合。将值摊销与跨层低秩键压缩配对得到 LowRAM 非对称压缩管线，在三个模型家族上保持接近无损；由于每步解码只需重建选定的 KV 子集，解码开销极小，在 4× 压缩下峰值解码吞吐最高提升 5 倍。LowRAM 还进一步与量化、驱逐组合：长上下文下达到 26.9× 压缩、保持基线 94.5% 的性能——证明把键与值当作结构上不同的对象，能实现高效、激进且可组合的 KV Cache 压缩。
   - **核心创新点**：
     1. 按头值缓存摊销（键预测值）
     2. 跨层低秩键压缩互补
     3. 与量化/驱逐可组合压缩

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：值缓存摊销——每个注意力头在测试时拟合一个小型预测器（可元学习初始化），以键为输入预测值向量，仅对重建误差最大的 token 存残差；键侧用跨层低秩投影压缩。解码时按需只重建选定的 KV 对，保持低开销；整体管线支持与量化、驱逐策略叠加。
   - **实验结果**：4× 近无损值压缩；4× 压缩下峰值解码吞吐最高 +5×；与量化+驱逐组合达 26.9× 总压缩，长上下文保持基线 94.5% 性能；三个模型家族上接近无损。
   - **局限性**：值预测质量依赖头内键-值相关度，相关度低的头压缩裕量小；测试时拟合预测器引入额外开销，一次性拟合场景（如多查询推理）更适用。
   - **链接**：https://arxiv.org/abs/2611.07025

   </details>

   - **逻辑**：为维持榜单与商业竞争力，模型厂商加速迭代，新模型发布常伴随旧模型行为的隐性变化；当官方缺乏透明变更说明时，用户把效果波动归因于"被削弱"，信任成本随之上升，监测与投诉随之涌现。
   - **预测**：透明变更日志会从"可选项"变成模型供应商的标配，围绕模型行为漂移的第三方监控、评测与回归测试工具将迎来新的市场空间。

   - **预测**：下一阶段视频模型竞争将围绕因果一致性评测基准与 Agent 化控制范式展开，代码与 3D 中间表示有望成为可控视频生成的标配，视频评测基准也会从"画质榜"扩展出"因果榜"。

   - **现象**：LowRAM 把 KV Cache 压到 26.9× 且保持 94.5% 性能、CPU-ARC 让推理缓存调用成本降到 1/16–1/291、DeepX 宣称 100B 参数推理功耗低于 5W——从压缩算法到推理框架再到专用芯片，多点开花。
   - **逻辑**：长上下文与端侧部署把显存和功耗矛盾推到前台，业界开始从容量、带宽之外的"结构冗余"（值可由键预测、推理轨迹可复用、存内计算省去搬移）寻找突破口，压缩不再只是精度取舍。
   - **预测**：KV 压缩、推理缓存与低功耗芯片三条线将相互叠加，未来一两年内同等算力下的长上下文推理成本可能再降一个数量级，端侧百亿参数推理将转向真实的工程落地。
