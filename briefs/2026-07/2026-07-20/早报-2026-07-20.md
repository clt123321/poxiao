### Tier 1 · 核心突破

1. **从预训练到后训练理解推理（Understanding Reasoning from Pretraining to Post-Training）**

   🔬 领域：LLM 推理 · 后训练 · 规模律 · 热度：HF Top 3

   - **一句话核心贡献**：系统研究预训练选择（模型大小、数据）如何影响 RL 后训练的收益，以及 RL 后训练究竟对模型做了什么，填补预训练与后训练研究长期割裂的空白。
   - **摘要精译**：
     RL 后训练在提升 LLM 推理能力方面效果显著，但现有研究几乎将其与预训练割裂开来独立研究，导致两个核心问题悬而未决：预训练选择如何决定 RL 的回报上限？RL 后训练本质上在改变模型的什么？
     本文通过大量受控实验，系统追踪预训练规模、数据混合比例与 RL 后训练效果的关系，发现预训练质量和模型规模是 RL 能否有效提升推理的关键先决条件，存在"RL 响应性阈值"。
     实验还揭示 RL 后训练的机制：主要通过增强模型的"已有推理能力的激活概率"而非习得全新能力，类似从"能做但不稳定"到"能稳定做"的转变。
   - **核心创新点**：
     1. 发现预训练质量决定 RL 后训练的回报上限
     2. 揭示 RL 主要激活已有能力而非习得新能力的机制
     3. 存在"RL 响应性阈值"：预训练不足时 RL 后训练无效

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：控制预训练数据量、质量、模型大小三个维度，对每个配置进行相同的 RLVR 后训练，对比结果；同时通过激活分析和知识探针追踪 RL 对内部表示的影响。
   - **实验结果**：预训练 token 数<100B 的模型对 RL 几乎无响应；100B-500B 之间响应性快速上升；>500B 后 RL 效果趋于稳定，主要体现在已有能力的稳定性提升。
   - **局限性**：实验规模受计算预算限制，超大模型的行为是否完全一致待验证。
   - **链接**：https://arxiv.org/abs/2607.16097

   </details>

2. **Recursive Harness Self-Improvement：递归框架自我改进**

   🔬 领域：Agent 框架 · 自我改进 · 训练数据生成 · 热度：HF Top 5

   - **一句话核心贡献**：提出框架（harness）不仅是推理时的脚手架，更是生成训练数据的组件——通过优化框架执行轨迹的质量，实现对未来基础模型训练的正向影响，形成框架-模型协同进化闭环。
   - **摘要精译**：
     在模型-框架协同进化的视角下，框架的执行轨迹会成为未来模型训练数据，因此框架优化不仅影响当下 Agent 性能，还影响未来模型的能力上限。
     本文研究 harness-in-the-loop 学习：同时优化框架对当前任务的性能和其生成轨迹的训练价值，通过递归自我改进使框架持续提升轨迹质量，减少对人工更新的依赖。
     在代码生成和工具调用任务上，递归自我改进框架生成的轨迹训练的后继模型，比原始框架训练的模型在相同任务上性能提升 9-14%。
   - **核心创新点**：
     1. 框架作为训练数据生成器的新视角
     2. 框架执行质量和轨迹训练价值的联合优化
     3. 后继模型能力提升 9-14%

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：设计框架质量评估指标（步骤清晰度、工具调用正确性、推理可追溯性），通过进化搜索优化框架提示词和结构，定期将优质轨迹加入下一轮训练数据。
   - **实验结果**：在 HumanEval-Agent 和 ToolBench 上，第 3 代递归改进框架训练的模型分别提升 14% 和 9%。
   - **局限性**：递归改进收敛速度取决于任务反馈质量；对开放性任务的效果评估困难。
   - **链接**：https://arxiv.org/abs/2607.15524

   </details>

3. **DSWorld：数据科学世界模型驱动高效自主 Agent**

   🔬 领域：数据科学 Agent · 世界模型 · 推理效率 · 热度：HF Top 6

   - **一句话核心贡献**：提出数据科学世界模型，能够在真实执行前预测数据操作的效果，将数据科学 Agent 从"反复试错"转变为"规划后执行"，大幅降低计算成本。
   - **摘要精译**：
     自主数据科学 Agent 在数据理解和决策能力上表现强劲，但仍严重依赖反复试错工作流，每次迭代都需要真实运行计算密集型代码，导致效率极低。
     DSWorld 训练一个"数据科学执行环境模拟器"，能够预测在数据集上执行特定操作（groupby/merge/transform 等）后的状态变化，让 Agent 在虚拟环境中规划后再执行。
     实验显示，基于 DSWorld 的 Agent 在典型数据科学任务上计算成本降低 60%，任务完成率提升 12%，尤其在复杂多步操作规划场景优势显著。
   - **核心创新点**：
     1. 数据科学执行环境世界模型，消除反复试错
     2. 虚拟规划-真实执行框架，先预测后执行
     3. 计算成本降低 60%，完成率提升 12%

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：在大量数据科学代码执行日志上训练世界模型，输入（操作代码+当前数据集描述）→ 输出（预测执行后数据集状态）；Agent 通过世界模型规划操作序列后再批量执行。
   - **实验结果**：在 DS-1000 数据集上，任务完成率 67.3%（vs 基线 60.1%），平均执行次数从 8.3 次降至 3.1 次。
   - **局限性**：世界模型对罕见操作或新 API 的预测准确性较低；超大数据集的状态表示仍是挑战。
   - **链接**：https://arxiv.org/abs/2607.15901

   </details>

### Tier 2 · 工程改进

4. **Loopie：最强循环 Transformer MoE 模型**

   🔬 领域：Transformer 架构 · 参数效率 · 循环推理 · 热度：HF Top 7

   - **一句话核心贡献**：通过 MoE + 循环 Transformer 的组合解决循环 Transformer 的长期性能瓶颈，证明在等效计算预算下循环架构可以超越非循环基线，提供最强的循环推理基础模型。

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：20B 总参数 / 2B 激活（大版本）和 6B/0.6B（小版本）的 MoE 循环 Transformer；通过专家专化和循环次数动态调整解决循环效率问题。
   - **实验结果**：在等效 FLOPs 下，Loopie-20B 在推理 benchmark 上超越同计算量非循环模型 7-9%；参数量仅 2B 激活但性能接近 7B 密集模型。
   - **链接**：https://arxiv.org/abs/2607.16051
   </details>

## 📊 今日总结

1. **预训练质量是 RL 后训练效果的决定性前提**：今日论文揭示 RL 主要是激活已有能力而非习得全新能力，且存在"预训练质量阈值"——这意味着对于能力不足的基础模型，再多的 RL 后训练也无法带来质变；背后逻辑是 RL 本质是一个搜索过程，需要模型在参数空间中"已经存在"正确解；预计这一发现将推动业界更重视预训练阶段的数据质量和多样性投入，而非单纯依赖后训练提升。

2. **Qwen3.8 的发布标志着开源代码推理模型进入旗舰水平**：2.4T MoE 架构的代码 Agent 能力接近 Claude 3.7/GPT-4o 级别，且本地可部署；背后逻辑是 Qwen 团队在 MoE 架构和代码专项训练上持续深度投入，加之国内庞大的代码数据资源优势；预计 2026 下半年以 Qwen3.8 为核心的本地 AI 编程助手生态将快速成熟，重塑开发者工具市场格局。

3. **AI 基础设施安全的系统性短板正在暴露**：HuggingFace 安全事件的不对称困境、BadWAM 的具身 AI 安全漏洞、多层 Agent 红队框架的需求同步出现，表明 AI 系统安全已从"事后应对"进入"系统性建设"阶段；预计 AI 安全将在 2026-2027 年成为与算法能力并列的核心竞争维度，相关标准化工作将加速推进。
