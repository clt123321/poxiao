2. **Echo-Infinity：实时无限视频生成与进化记忆**

   🔬 领域：视频生成 · 自回归模型 · 长视频 · 热度：HF #10

   - **一句话核心贡献**：提出 Echo-Infinity 自回归框架，通过可学习的"进化记忆"动态过滤并压缩任意长历史，以恒定代价实现实时无限时长视频生成。
   - **摘要精译**：
     现有视频生成方法面临两大核心矛盾：若要保持历史一致性则必须保存大量 KV 缓存（代价随时长线性增长），若压缩则不可避免丢失关键细节。Echo-Infinity 受人类记忆巩固机制启发，引入一个可学习的进化记忆模块，能够从任意长度历史中动态筛选、抽象并压缩信息，且内存开销为常数级——无论视频已生成多少帧，显存占用恒定。实验表明，Echo-Infinity 在标准视频生成基准上超越此前所有自回归基线，且在 1000+ 帧的生成场景中保持显著更优的时序一致性，压缩带来的信息损失降低约 40%。
   - **核心创新点**：
     1. 可学习进化记忆：对历史自适应过滤，非手工 KV 调度
     2. 恒定显存代价：无论视频长度，内存不随帧数增长
     3. 缓解自回归噪声累积，时序一致性大幅提升

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：在自回归 Transformer 基础上添加进化记忆层，每生成一帧后更新记忆状态，通过注意力门控机制决定哪些历史信息需被保留、哪些可以丢弃，类似人类工作记忆与长期记忆的转换。
   - **实验结果**：在 UCF-101、Kinetics 等视频生成基准上超越 RWKV-Video、VideoMamba 等自回归基线；1000 帧生成中，时序一致性（CLIP 相似度）比最强基线高出约 8 个百分点。
   - **局限性**：进化记忆模块需要额外训练步骤，对预训练模型适配有一定工程成本；超长视频场景下记忆更新策略的最优设计尚需探索。
   - **链接**：https://arxiv.org/abs/2606.04527

   </details>

3. **Audio-Interaction Model：首个统一在线音频交互大模型**

   🔬 领域：音频 AI · 流式大模型 · 多任务 · 热度：HF #1

   - **一句话核心贡献**：提出 Audio-Interaction，将离线音频模型与流式 ASR、语音聊天等任务统一为单一在线模型，实现实时感知-决策-响应闭环。
   - **摘要精译**：
     音频本质上是交互性模态——需要实时感知环境变化并即时做出反应，但现有大型音频语言模型（LALM）均为离线设计，流式模型也各自只能处理单一任务（如流式语音识别或语音聊天），缺乏统一的在线能力。本文形式化定义了"音频交互模型"这一新范式，要求模型以"始终在线感知-决策-响应"循环实时处理声音、环境和指令，并能在不同任务间动态切换。Audio-Interaction 实现该范式，在标准音频理解和生成基准上不仅匹配甚至超越专用单任务模型，同时支持多语言实时翻译与声景理解等新型能力，整体延迟降低约 35% 相比同类流式方案。
   - **核心创新点**：
     1. 首次统一在线/离线音频任务于单一模型框架
     2. 实时感知-决策-响应循环设计，延迟降低 35%
     3. 支持环境声音感知 + 语音指令 + 多语言同步翻译

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：采用流式 Transformer 编码器接受实时音频输入，通过状态空间模型维护跨帧上下文，决策头根据当前任务需求动态激活对应解码分支（ASR/TTS/音频问答等）。
   - **实验结果**：在 AIR-Bench 音频理解基准上超越现有 LALM；在流式 ASR（LibriSpeech）上 WER 降至 2.3%，优于专用流式模型；语音聊天延迟 < 200ms。
   - **局限性**：多任务统一带来训练复杂度上升；在噪声环境下感知精度相比降级到专用模型略有损失。
   - **链接**：https://arxiv.org/abs/2606.05121

4. **ThoughtFold：通过内省偏好学习折叠推理链**

   🔬 领域：推理模型 · 强化学习 · 链式推理 · 热度：HF #8

   - **一句话核心贡献**：针对大型推理模型（LRM）的过度思考问题，提出 ThoughtFold 框架，通过内省偏好学习"折叠"冗余推理步骤，在保持准确率的同时将推理链长度压缩约 30%。
   - **摘要精译**：
     基于 RLVR（Verifiable Rewards 强化学习）训练的大型推理模型能够生成长推理链，但长链中天然包含大量试错和冗余探索，而现有 RLVR 方法选择正确轨迹进行记忆化时，这些冗余步骤被一并强化，导致"过度思考"问题——模型即使在简单问题上也生成不必要的长推理链。ThoughtFold 引入内省偏好学习：让模型对自身推理链进行自我批判，识别哪些步骤真正有贡献、哪些是冗余探索，然后通过偏好优化压缩推理链，只保留关键步骤。实验显示，ThoughtFold 在 MATH 500、LiveCodeBench 等基准上准确率不降，同时推理 token 消耗减少约 30%，推理效率显著提升。
   - **核心创新点**：
     1. 内省偏好学习：模型对自身推理链进行质量评估
     2. 结构感知压缩：识别冗余试错步骤而非简单截断
     3. 推理链压缩 30%，数学/代码基准准确率维持不变

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：在标准 RLVR 框架上增加一个内省奖励信号：对每条推理轨迹，让同一模型判断哪些中间步骤是冗余的，形成偏好对（完整链 vs 折叠链），再通过 DPO 类优化使模型偏向生成更简洁的正确链。
   - **实验结果**：MATH 500 准确率与基线 Qwen3-7B 持平（87.2% vs 87.4%），推理 token 数从平均 2,847 降至 1,993（减少 30%）；LiveCodeBench Pass@1 提升 1.2%。
   - **局限性**：内省偏好标注依赖模型自身判断，可能在困难问题上误删有效推理步骤；当前实验主要在数学/代码任务验证。
   - **链接**：https://arxiv.org/abs/2606.03503

   </details>

   - **摘要精译**：

     2. 揭示数据组成和任务混合比例是被低估的关键变量
     3. Qwen-Image-Flash 在 2-4 步内达到接近全步模型的生成质量

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **局限性**：配方结论可能对其他架构（如 DiT、UNet）泛化性有限，需针对各架构重新搜索最优配方。

6. **StreamMA：多 Agent 推理的流式通信范式**

   🔬 领域：多 Agent · 推理效率 · 流水线优化 · 热度：HF #9

   - **一句话核心贡献**：StreamMA 将多 Agent 系统从"生成后传输"改为"逐步流式传输"，实现 Agent 间流水线并行，端到端延迟随流水线深度不再线性增长，同时生成质量意外提升。
   - **摘要精译**：现有多 Agent 推理强迫每个 Agent 等待上游 Agent 生成完整结果后再开始处理，使延迟与流水线深度成正比。StreamMA 让每个 Agent 将推理步骤实时流式传递给下游，下游 Agent 可以基于上游可靠的早期推理步骤并发工作（早期步骤误差率更低），从而同时降低延迟并减少晚期错误步骤的负面影响。
   - **核心创新点**：逐步流式传输、流水线并行、基于推理步骤可靠性的早期利用

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：为标准 Transformer 解码添加流式 token 发送机制，下游 Agent 通过滑动窗口注意力接收增量推理步骤。
   - **实验结果**：4 层流水线场景下端到端延迟减少约 52%，MATH 多 Agent 协作准确率提升 3.4%。
   - **局限性**：流式通信对网络带宽要求较高，本地离线场景无法完全发挥优势。
   - **链接**：https://arxiv.org/abs/2606.05158

   </details>

7. **ZipSplat：更少高斯，更优三维场景重建**

   🔬 领域：三维重建 · 3D 高斯泼溅 · 前馈模型 · 热度：HF #19

   - **一句话核心贡献**：ZipSplat 将 3D 高斯泼溅从"每像素一个高斯"解耦为基于场景复杂度的自适应分配，用少得多的高斯实现同等甚至更好的重建质量。
   - **摘要精译**：现有前馈高斯泼溅方法将表示预算与相机分辨率绑定，导致平坦区域和复杂区域生成等量的高斯，资源严重浪费。ZipSplat 引入基于 k-means 聚类的多视角 token 压缩，自动将高斯集中到纹理复杂、几何变化丰富的区域，高斯数量减少 60-80% 的同时，重建 PSNR 提升约 1.2dB。
   - **核心创新点**：高斯密度自适应场景复杂度、k-means token 压缩、解耦像素网格与表示预算

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：多视角 ViT 提取密集 token，经 k-means 聚类压缩到自适应数量的高斯核，每个高斯携带完整 3DGS 属性（位置/旋转/不透明度/颜色球谐系数）。
   - **实验结果**：RealEstate10K 测试集 PSNR 从 26.1dB 提升至 27.3dB（+1.2dB），高斯数量减少 70%，渲染 FPS 提升 2.1×。
   - **局限性**：k-means 聚类超参数对不同场景类型需调整；对完全无纹理区域（如白墙）聚类效果退化。
   - **链接**：https://arxiv.org/abs/2606.05102

   </details>

8. **AAD-1：单步自回归视频生成的非对称对抗蒸馏**

   🔬 领域：视频生成 · 对抗蒸馏 · 单步推理 · 热度：HF #17

   - **一句话核心贡献**：AAD-1 通过生成器-判别器不对称设计（生成器保持因果注意力、判别器使用双向注意力），解决了单步自回归视频生成中的动作崩溃和训练不稳定问题。
   - **摘要精译**：对抗蒸馏是将多步扩散模型压缩为单步生成的主流方法，但在自回归视频生成中普遍出现动作崩溃（生成静止或重复帧）和训练不稳定问题。AAD-1 的关键洞察是：生成器与判别器无需对称——生成器采用因果注意力保持自回归采样能力，判别器则采用双向注意力看到完整时空上下文以提供更精准的真实性判断信号，两种不对称性的组合使训练稳定性大幅提升，生成动态性恢复正常。
   - **核心创新点**：非对称架构设计（因果生成器 + 双向判别器）、单步生成动态性保持

   <details>
   <summary>💡 展开详情</summary>

   - **方法细节**：在 CogVideoX 自回归基础架构上，将判别器替换为双向 Transformer 变体，并在对抗训练损失中加入时序运动正则项防止动作崩溃。
   - **实验结果**：EvalCrafter 综合评分从对称蒸馏基线 72.3 提升至 79.8；UCF-101 FVD 从 412 降至 287（降低 30%）；推理速度 25× 提升。
   - **局限性**：非对称设计使判别器训练内存增加约 40%；超长视频（>128 帧）的判别器双向注意力计算成本较高。
   - **链接**：https://arxiv.org/abs/2606.03972

   </details>
