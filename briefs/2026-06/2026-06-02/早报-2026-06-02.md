### 🔴 Tier 1 — 视频与推理效率（今日双重焦点）

1. **VideoMLA：长视频扩散的低秩 KV 缓存**

   🔬 领域：视频生成 · 推理效率 · 热度：HF #1

   - **一句话核心贡献**：提出低秩潜变量 KV 缓存方法 VideoMLA，将分钟级自回归视频扩散的 KV 显存占用大幅压缩，同时不依赖固定滑窗布局，实现了更灵活、更高效的长视频生成。
   - **摘要精译**：
     长时序因果视频扩散模型目前普遍采用固定大小滑动窗口 KV 缓存，近期进展主要集中在改变窗口内哪些 token 被保留或如何编码位置，而 KV 缓存本身的"每头布局"作为流式显存和计算的主导因素，却鲜有人从根本上重新设计。VideoMLA 从 Multi-head Latent Attention（MLA）中汲取灵感，将 KV 缓存压缩为低秩潜变量表示，在不改变模型输出分布的前提下，将 KV 显存占用降低 60% 以上。实验表明，在分钟级视频生成任务（>1000 帧）上，VideoMLA 比标准 KV 缓存节省 62% 显存，推理吞吐量提升约 1.8×，生成质量（FVD/CLIP）与基线持平。
   - **核心创新点**：
     1. 将 MLA 低秩 KV 压缩引入视频扩散，KV 显存降低 62%
     2. 不修改滑窗布局，兼容现有主流长视频扩散架构
     3. 1000帧以上视频推理吞吐量提升 1.8×，质量无损

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：在视频扩散模型注意力层引入低秩潜变量 KV 压缩，每个注意力头的 KV 矩阵分解为低秩因子乘积，存储低秩因子而非完整 KV；兼容 FlashAttention 等高效注意力实现
   - **实验结果**：在 UCF-101、WebVid-10M 长视频子集上验证；KV 显存降低 62%；FVD 与标准 KV 缓存相差 <1%；推理速度提升 1.8×
   - **局限性**：低秩压缩对细粒度时序细节（如快速动作）的保留效果有待进一步评估；目前仅验证在 1000 帧内，超长视频效果未知
   - **链接**：https://arxiv.org/abs/2605.30351

   </details>

2. **投机流水线解码：零气泡高精度推理加速**

   🔬 领域：推理加速 · LLM 效率 · 热度：HF #6

   - **一句话核心贡献**：提出投机流水线解码（SPD），通过流水线并行化草稿生成与验证过程，消除标准投机解码中的"气泡"等待问题，在低并发场景下实现更高加速比（实测比标准方案快 1.4-2.1×）。
   - **摘要精译**：
     投机解码通过"小模型起草 + 大模型验证"范式加速 LLM 低并发推理，但主流方法依赖多 token 预测，随着草稿长度增加预测难度指数级上升，且草稿生成与验证串行执行造成显著的流水线气泡。SPD 将草稿生成与验证流水线化：当大模型验证第 k 步草稿时，小模型同步生成第 k+1 步草稿，两阶段零重叠，消除气泡等待。在 Llama-3-70B + Llama-3-8B 组合上，SPD 实现了 2.1× 加速，比标准投机解码高出 43%，接受率提升 8 个百分点。
   - **核心创新点**：
     1. 草稿生成与验证流水线并行，彻底消除串行气泡，加速比提升 40%+
     2. 不依赖多 token 预测，规避预测难度指数上升问题
     3. 在 70B 模型上实现 2.1× 加速（标准方案约 1.5×）

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：将投机解码分解为草稿阶段（小模型）和验证阶段（大模型）的流水线，借助 CUDA stream 并行调度；验证失败时动态调整草稿长度
   - **实验结果**：Llama-3-70B/8B 组合上加速 2.1×（基线 vLLM 投机解码约 1.47×）；接受率 82.1% vs 74.5%；在 batch_size=1 场景下优势最显著
   - **局限性**：在高并发（batch_size>8）场景下优势缩小；小模型与大模型词表需严格对齐
   - **链接**：https://arxiv.org/abs/2605.30852

   </details>

3. **ESPO：早停近端策略优化——节省 RL 训练无效算力**

   🔬 领域：强化学习 · LLM 训练 · 热度：HF #5

   - **一句话核心贡献**：提出早停近端策略优化（ESPO），当 LLM 在 RL 训练中早期出错时，不再强制生成至最大长度，而是及时停止，节省了 30-50% 的训练 token 并稳定了优势估计，加速收敛。
   - **摘要精译**：
     LLM 在 RL 训练中，若早期推理步骤出错，标准算法（PPO/GRPO）仍强制模型继续生成至最大 horizon，这既浪费了失败后所有 token 的计算资源，也污染了优势函数估计（后续 token 的收益完全基于已经失败的前提，信号噪声大）。ESPO 引入动态早停机制：通过在线判断当前推理轨迹是否可挽救，若判定失败则立即停止生成，将计算资源聚焦在有效轨迹上。在 GSM8K、MATH、HumanEval 等推理基准上，ESPO 相比标准 PPO 训练 token 减少 38%，最终准确率提升 2.1-3.4 个百分点，收敛速度提升约 1.5×。
   - **核心创新点**：
     1. 动态早停机制，避免失败轨迹的无效计算，节省 38% 训练 token
     2. 优势估计质量显著改善，因去除了后失败污染的噪声信号
     3. 收敛速度提升 1.5×，在数学/代码推理任务上效果最显著

   <details>
   <summary>💡 展开详情（方法论 + 实验）</summary>

   - **方法细节**：在 PPO 训练循环中引入在线轨迹质量评估器（基于当前 reward 信号和历史统计）；判定失败后终止当前 rollout，跳过该样本的后续 token 生成；compatible with GRPO/PPO
   - **实验结果**：GSM8K: +2.1pp vs PPO; MATH: +3.4pp; HumanEval: +2.8pp；训练 token 减少 38%；在相同 token 预算下性能全面超过标准 PPO
   - **局限性**：早停判断器本身需要调参（阈值设置）；在开放生成任务（创意写作）上是否适用尚未验证
   - **链接**：https://arxiv.org/abs/2605.29860

   </details>

## 📊 今日总结

**现象**：Computex 2026 周一正式拉开帷幕，英特尔 480GB VRAM Crescent Island GPU 是今日最大冲击性发布。同时，HF Papers 呈现出明显的"效率深耕"趋势——VideoMLA 把 KV 缓存压缩进视频扩散、SPD 消除推理气泡、ESPO 节省 RL 训练 token——三篇独立工作不约而同指向"用更少算力做更多事"的同一方向。

**逻辑**：AI 算力成本仍是限制规模化落地的核心瓶颈，因此从训练（ESPO）、推理（SPD/VideoMLA）到存储（KV Cache 优化）的全链条效率提升成为学界最密集的研究方向。英特尔 480GB 产品的逻辑也相同：不靠算力突破，而靠超大显存容量绕开显存瓶颈，为超大模型本地化开辟新路径。"只有两款模型"帖子的爆火则反映了社区在信息过载后的理性收敛——生态成熟的标志之一是从"什么都试"走向"聚焦最优解"。

**预测**：英特尔 Crescent Island 若软件生态（OpenCL/SYCL 对 CUDA 的兼容覆盖）在 2026 Q3 前达到 80% 以上，将在超大模型研究机构中占据一席之地，驱动英伟达大显存 SKU 价格在 2026 Q4 下降 15-20%；SPD 类流水线投机解码将在 2026 Q3 前被 vLLM/TGI 主干集成，成为默认低并发推理策略；ESPO 早停机制将对 RL 后训练基础设施产生影响，预计 2026 年底出现首批基于 ESPO 思想的开源训练框架。
